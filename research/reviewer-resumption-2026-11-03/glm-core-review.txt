Three findings worth your attention
F2 (the subtle one): in decode(), cached.insert() runs before next = best(...). If best() throws (non-finite logits), next is stale while cached grew — the fast path prefix==cached && next>=0 would then emit a wrong token. Today nl_call's catch-all e.reset() masks this, at the price of wiping the cache on every error, including malformed requests. Fix is two lines: next = -1; right after the successful decode, then narrow the catch-all. Anyone who "optimizes away" the reset without this introduces a wrong-output bug.
F1: the header documents parse_special as "Allow tokenizing special and/or control tokens which otherwise are not exposed and treated as plaintext." Any untrusted text containing <|eot_id|>-style markers becomes special tokens (after chat-template application, too). The engine offers no special=false primitive, so a correct host can't be built today — smallest fix: optional special/add_special request fields + document the token-array composition pattern the ID-level API already supports.
F6: llama_model_params has no abort callback (only progress_callback — which does abort load when it returns false: that's the 3-line fix), and the context abort_callback is documented "currently works only with CPU execution" — material since load accepts gpu_layers up to 999.

Tests (T1–T12 in the report): highest-value are the cache-invariant property test vs. a cold-run oracle (both build flags), verify vs verify_serial differential, the F6 error-path cache-preservation test (fails before the fix), and ABI destroy/cancel-during-call stress.
