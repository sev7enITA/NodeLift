## Verified project baseline

NodeLift public repository: https://github.com/sev7enITA/NodeLift at commit 53c070b821900246894b87c037303a8cba54af4f. Native dependency llama.cpp ddf48f85c933c1f438212a02eb21e7b001d2d37d. Mac M3 Max, 64 GiB. Android/iOS companions keep a complete small draft resident and return token IDs. The complete target stays on the Mac. No target sharding, pooled RAM or independent remote-task execution is implemented. Host tokenizes; compatibility checks an ordered token-semantics fingerprint, not just vocabulary size. Pinned TLS, host leases, epochs, sequences and exact prefix checking exist. Android supports bounded one-block lookahead; iOS does not advertise it. Only greedy verification is in this experiment; do not claim a stochastic distribution-preserving algorithm.

Measured Mac pilot: Llama 3.1 8B Q4_K_M target, Llama 3.2 1B Q4_K_M draft, three prompts, three repetitions, 128 output tokens, context 2048, Metal. Paired median ratios relative to each harness's host-only reference: serial k4 0.793x (9/9 identical outputs); serial bounded lookahead k4 0.665x (9/9); batch k4 1.291x (6/9); batch bounded k4 1.049x (6/9). Separate upstream llama.cpp draft-simple k4 achieved 1.448x (6/9), against its own HTTP reference. These are a small pilot, not a universal result or a cross-harness absolute speed comparison.

Both batch harnesses diverged at generated index 36, token 6104 versus 5810, on one prompt in all repeats. An identical-token-prefix probe found that changing only current batch width with serial KV construction did not flip the argmax in 13 tested windows. Building history in width 3 or 5 AND evaluating current width 5 did reproduce the flip. Serial A/A controls remained equal. Serial top-two logit margin 0.04478836; maximum absolute logit difference 0.14352226. This does not isolate a particular kernel or prove corruption. KV numerical values can change through arithmetic even with valid positions/masks. Matching output tokens alone does not imply equal KV. A top-two margin heuristic without a justified global error bound is not exact verification.

Physical Android 0.2.13 O3 attempts with the same 8B/1B pair: host 3.707 s versus remote bounded 17.879 s; second host 5.241 s versus remote 19.101 s. Both interrupted at sequence 9 after 26 of 36 draft tokens accepted, with 10-second expiry and approximately 2-second cleanup. Outputs matched after fallback. A later diagnostic reached the HTTPS server's 32 connection slots. The host now closes companion TLS responses and passed a 40-client regression, but there is no physical post-fix repeat. Do not extrapolate interrupted runs into normal remote speed, or the same-Mac bounded slowdown into phone contention.

Resident task pilot on this Mac only: two small Qwen models, six fictional records, 48 attempts. 0/48 met the strict bare-JSON contract (all added fences, some had semantic errors). Relevant-record messages reduced median serialized bytes 58.1%. This is not useful distributed throughput, not a held-out evaluation, and not proof small models cannot work with constrained decoding. No complete-task mobile protocol exists yet. Existing single-model prefix reuse and a deferred-draft-cache flag are studied separately; do not relabel upstream caching as an invention.

## Candidate directions to challenge

A. Serial-equivalent multi-column verifier: share weight reads across proposed tokens but preserve each token's declared arithmetic reduction order, causal attention, KV history and sampling. Compare with the current serial oracle; a new fixed-shape oracle is a separate, explicitly changed contract. Determine what must be invariant beyond GEMM, and whether fixed-width replay inspired by LLM-42 helps without silently changing that oracle. Reject unjustified exactness claims.

B. Remote draft as an optional producer, with bounded preemption and host progress: use a proposal only when its epoch/prefix and deadline still match; invalidate late work without stalling the main loop. Initially never allow concurrent unsynchronized mutation of the same target/KV handle. Does this actually save target work or only cap losses under serial verification? How can it beat the best local draft when batching becomes qualified? Name hidden polling/queue/recovery costs.

C. Move work to its resident cache: route a whole eligible request or independent task to a qualified worker with the exact prefix/model state, instead of moving large KV tensors. Separately consider storing host-generated opaque KV snapshots on spare devices as a memory/storage tier. For snapshots, require exact runtime/layout provenance, integrity, privacy scope, capacity reservation and measured serialization/upload/download/import costs. Never assume Android draft KV is compatible with the Mac target. Compare local RAM, local SSD, recomputation and remote storage. Identify conditions under which this saves TTFT or adds practical capacity.

D. Throughput lane: independent grounded tasks with constrained output, evidence validation and deterministic decomposition. Compare against a continuously batched host baseline at equal quality, including dispatch, validation, repair, final synthesis and failures. Could an office with multiple requests benefit even if a single chat does not? Define a smallest useful mobile protocol and a genuine held-out evaluation. Also evaluate cross-request remote drafting once the verifier is qualified; current host engine is single-run, not a production multi-request scheduler.

E. Capacity lane: explicit layer-owned workers on desktop GPUs with local KV, measured placement, microbatching across independent requests and failure-aware leases. Distinguish a model exceeding one machine's budget from a latency improvement. RAM and VRAM allocation need separate accounting except unified memory; include workspace and copies. Do not assume generic RPC is tensor parallelism. Do not assume every node needs all layers' KV. If no surviving placement fits, a local fallback does not exist.

## Primary research leads, read separately by the coordinator

These are leads and bounded summaries, not evidence that their results transfer to NodeLift:
- Thinking Machines, batch-invariant kernels: https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/ . Matrix multiplication, normalization and attention can require shape-independent reductions.
- Microsoft Research, LLM-42: https://arxiv.org/abs/2601.17768 . Fixed-shape verification/rollback and replacement of candidate KV. Fixed-shape consistency must not be confused with our existing serial output contract.
- Speculation at a Distance: https://arxiv.org/abs/2606.25091 . Separates single-request latency from multi-client throughput; its equal contention-free service-time assumptions need replacement by measured configuration-specific times on our hardware.
- Distributed prompt caching: https://arxiv.org/abs/2602.22812 . Remote state catalog with Bloom-filter hints, tested on Raspberry Pi/Gemma. A catalog hit is not compatibility/integrity proof, and those published percentages are not Mac measurements.
