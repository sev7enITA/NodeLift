# Batch-shape experiment plan

Frozen before numerical runs on 2 November 2026. Question: with the same model, exact token window and freshly prefilled preceding KV state, does batched evaluation differ from repeated one-token evaluation? Distinguish this from an identical-shape serial A/A control and from whole-request output drift.

Use the pinned NodeLift llama.cpp source, Qwen2.5 1.5B Instruct Q4_K_M, the same generic prompts already used in native correctness checks, eight requested threads, context 512, requested GPU layers 0 and 999, and requested flash attention on and off. Each case supplies a sequence generated beforehand using the same target; inputs are fixed within an experiment. At each position and width 1, 4 or 8, independently clear three contexts and prefill exactly the same prefix. Feed the same authoritative window serially into two of them and as one block into the third. Compare top-1 IDs, top-2 margins and maximum absolute vocabulary-logit differences. Record per-window durations but do not treat their order-fixed values as a performance benchmark. Positions are correlated within a single session; report denominators and retained failures.

Prioritize the Italian prompt near the previously observed token 23 mismatch, plus short English and code prompts. Windows beyond a sequence's generated length are omitted and recorded via the generated case file. This is a targeted exploratory corpus, not a representative estimate of production flip rates. No claim about the exact cause follows unless the evidence separates plausible causes. Requested GPU layers and flash-attention flags are not independent attestation of backend allocation or actual kernel choice.

Run a separate 0.5B target as a control if execution succeeds. Include a width-1 check and a serial-repeat control; report any failure rather than repairing or silently replacing a sample. No remote phone or PC inference is performed. No environmental power or acceleration claim is derived from these tests.
