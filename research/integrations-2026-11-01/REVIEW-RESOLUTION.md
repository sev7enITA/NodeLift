# GLM review adjudication

GLM 5.3 Max reviewed the initial `model_library.py` and `providers.py` through the browser. The user authorized model assistance. Only source code and a description of existing authorization/controller invariants were supplied; no API keys, private prompts or runtime exports. The response is preserved in [GLM-REVIEW.md](GLM-REVIEW.md). This document distinguishes the model's findings from our own verification. The final patch was not sent for another GLM pass.

| Finding | Adjudication and action | Evidence |
|---|---|---|
| P1-1 worker launch / cleanup can leave transfer busy | Confirmed. Worker creation/start is wrapped in rollback; part creation failure also retires the job. Failed unlink records `cleanup_pending` and still reaches a terminal state. UI reports the cleanup condition. | Thread-start and cleanup-failure tests verify a subsequent transfer can start. |
| P1-2 partial disk write can skew append offset | Confirmed on the originally reviewed code. Actual file-size verification was already added before the review returned. Follow-up now checks on-disk length before/after every chunk, flushes/fsyncs before acknowledgment, and marks disk-write errors terminal. Retry of that failed transfer is rejected. | Injected partial-write/ENOSPC-style error; incorrect actual-size and offset/overrun tests. |
| P2-1 registry durability / silent reset | Confirmed. Atomic registry saves now fsync file and, on Unix, directory; retain a previous valid snapshot. Startup recovers that snapshot with a visible warning, or reports unrecoverable metadata and the manual re-import route. | Corrupt-main / valid-backup and corrupt-main / corrupt-backup tests. These do not simulate physical power loss or prove hardware durability. |
| P2-2 slow SSE line defeats deadline | Confirmed; fixed before the review returned. Bounded `read1` chunks enforce time/byte/partial-line checks between reads, with remaining-time socket limits. The transport is retained when HTTP connection ownership detaches, so cancellation can shut it down. | Partial-line clock test, oversize line test, retained-socket cancellation, Unicode byte fragmentation, real LM Studio stream smoke test. |
| P2-3 abandoned generator / overlapping streams | Conditional in the original module; the controller already serialized generation and did not store generators. Added explicit `closing(...)` in the controller and a module single-flight guard anyway. | Overlapping-stream rejection, explicit generator close, controller output-limit failure cleanup tests. |
| P2-4 network JSON shape failures | Confirmed. Validate outer objects, rows, architecture/pricing, Hub metadata, choices/deltas and usage before dereferencing. Fail with bounded ValueError messages and preserve the previous catalog. | Malformed Hub and provider catalog/event fixtures. |

We did **not** apply the suggestion to immediately mark a live download cancelled and permit another one to start: the existing worker must retire before its shared transfer slot/event can be reused. Otherwise a slow old worker could write into a new transfer. Launch rollback and guaranteed terminal cleanup fix the confirmed wedge without introducing that race. Socket/network idle waits remain bounded; no promise is made to undo remote work or charges.

Additional changes: atomic 0600 creation for parts/registry temporaries, reject `.`/`..` revision aliases, avoid deleting recent partials during startup, cap visible output before publishing it, preserve the selected Hub filename across language changes, and display readable model names with source labels.

Documented limits remain: no resume, no deduplication of repeated downloads, single host process/state directory, no automatic architecture conversion or universal GGUF compatibility. Registration of a user-owned file is not protection against that same user replacing it later. SSE completion requires a terminated event and `[DONE]` by the supported contract; truncated or minimally nonconforming streams fail rather than being guessed complete. Public source/privacy checks and model reviews do not establish operational efficacy or phone acceleration.
