# Independent design review and adjudication

3 November 2026. GLM 5.3 with Max effort and Gemini 4 Argon with High effort both returned completed static assessments of the supplied architecture and measurement protocol. Gemini also returned a completed correction response after receiving code-level clarifications and the measured local pilot. Neither model operated the application, inspected a phone or executed a benchmark. The tests and measurements in this directory were run locally by the implementation agent.

Private conversation references, accessible to the account owner: [GLM review](https://chat.z.ai/c/48b5a30a-4e83-4d40-b8fd-6d94d92bcd1c), [Gemini review](https://gemini.google.com/app/a67abc7d1f97e354). These are provenance pointers, not publicly readable benchmark sources. The following is an English adjudication summary, not a verbatim transcript.

| Reviewer finding | Disposition and evidence |
|---|---|
| Serial verification provides no target compute amortization | Supported by the algorithm and the slower local pilot. It is a correctness/control path. A universal wall-time impossibility theorem would overstate what was measured; wrapper and batching overhead can also vary. |
| Speculating beyond a fully proposed block can waste work and delay the next request | Accepted as an architectural risk. Prefix matching and one-worker bounds are tested. The Android single service thread cannot poll while doing lookahead. Do not infer phone contention from the local Metal experiment. |
| Negative prefix offsets, empty reusable suffix and KV rollback were alleged defects | Rejected as confirmed defects: explicit bounds are present, empty reuse triggers fresh drafting, and native sync compares the complete authoritative prefix before rolling back divergent KV. Dedicated tests cover the cases. Short nonempty proposals are allowed. |
| Every valid reuse must consume exactly one predicted token | Too broad. The usual full-block-plus-bonus path consumes one; initial work and terminal EOS/context/output-budget cases require separate treatment. Exact prefix equality remains the authorization rule. |
| Vocabulary equality was treated as merely a count | Rejected. The actual fingerprint hashes ordered token semantics; only the host tokenizes chat. Both model artifacts and the fingerprint are recorded. A draft model hash alone cannot establish target/draft token-ID compatibility. |
| Subtracting independently measured durations introduces absolute clock offset | Rejected. Constant offset cancels inside each duration. Clock rate, resolution, interval coverage and self-report reliability still matter; the residual is not network RTT. Negative residuals remain visible. |
| Timing/count partitions should be validated on ingestion | Accepted. The host rejects malformed/nonfinite/boolean timing values, impossible duration partitions and inconsistent lookahead count partitions, without allowing telemetry to authorize tokens. |
| ACK wait and failed/aborted native work are incomplete | Accepted limitation. Successful native and worker phases, late replies and reported lookahead are measured. Missing failure/cleanup reports remain unknown rather than zero. |
| Mobile throughput, Wi-Fi delays, thermal percentage and independent-token hit-rate formulas | Not evidence. These were illustrative assumptions in the first responses, not measurements of this phone/model/link. Gemini withdrew them in its correction response. |
| Matching upstream mismatch rates prove a particular Metal kernel is responsible | Too strong. We additionally found the same first divergent token index and IDs in both harnesses, which motivates kernel investigation. It does not isolate a kernel without a controlled numerical probe. |
| A logit-margin heuristic or making batch output canonical restores exactness | Rejected under the declared serial-equivalence contract. A changed reference is a changed contract. A heuristic margin requires a justified error bound and additional validation. |
| Local bounded slowdown proves Android enqueue-to-dispatch delay | Rejected. Those rows run on one Mac with separate native handles and Metal contention. They contain no Android queue evidence. |
| Keep upstream local speculation and ngram controls | Implemented. Widths 1, 4 and 8 were measured with the same artifacts and prompts. Each harness uses its own paired baseline. Confidence threshold is explicitly zero for the upstream draft arm. |

The subsequent identical-prefix numerical probe reproduces the same token flip when both candidate KV history construction and current batch shape are changed. Changing current shape alone with serial history did not flip top-1 in the 13 tested windows; serial repeat controls remain identical. This narrows the investigation to numerical history/shape interactions in the tested configuration without identifying a particular kernel. The reviewers did not review this later probe. A shared-weight multi-column kernel with serial-equivalent reductions remains a research proposal. Android physical timing is still needed before deciding whether preemption or a smaller block would help the actual wireless path.
