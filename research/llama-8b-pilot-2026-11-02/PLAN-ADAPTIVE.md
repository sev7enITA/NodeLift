# Follow-up: adaptive decision control

Planned after reviewing the initial fixed-width results and before this follow-up. On the same Mac and identical local 8B/3B model pair, compare three NodeLift controller routes: host-only, fixed local draft width 4, and the existing adaptive gate with local draft width 4. Use the same six generic prompts, two repetitions, a 64-token budget, context 2048, eight requested threads, requested GPU layers 999, and greedy decoding. Shuffle all 36 conditions using seed 20261102. Warm both models first, so host-only timing includes the same model residency as the other arms. Log every planned attempt, exact tokens, stop reason, timings, acceptance, fallback and gate decisions.

The choice of width 4 was informed by the previous two sessions, so this is exploratory, not a blinded confirmatory study. Record failure rows and do not replace failed samples. A gate that disables local draft or returns to host must not be counted as phone contribution or memory pooling. Metrics are controller timing, not network/client time. No energy, actual GPU assignment or thermals are independently measured. This is a separate third period on one physical Mac.
