# Upstream local-runtime control

Added after observing both NodeLift sessions and before building or running this upstream comparison. Use the same Llama 3.1 8B target, Llama 3.2 3B draft, six generic prompts, 64-token maximum, requested eight threads, GPU layers 999, context 2048, greedy sampling and two repetitions. Compare the pinned llama.cpp server in `none`, `draft-simple` width 4 and `ngram-mod` modes. The same tokenized prompts are sent to each arm. Restart and warm the server separately for each arm; randomize arm and prompt order with seed 20261031. Record server identity, source revision, complete per-request results, token equality, finish outcome and failures. Do not claim apples-to-apples absolute latency against NodeLift, because the server HTTP path, warmup, batching and lifecycles differ. Compare upstream modes against their own server host-only baseline. No phone or remote worker is used. No model weights are redistributed.
