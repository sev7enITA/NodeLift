# External design review and disposition

GLM-5.3 was selected in z.ai; Max effort had been selected in the same review session. The model reviewed the supplied protocol description and stated test scope, **not the source or physical devices**. Its response reports no observed defect and separates inference from untested areas. The response is retained in `glm-design-review.txt`; the earlier performance-methodology review remains separate from this pairing deliverable. Gemini 4 High was unavailable under the account quota observed earlier in this session (reset displayed as 1 November 08:45). No substitute Gemini model or successful Gemini QR review is claimed.

- **Optical density:** record RSA-2048 identity generation, QR version 27 / 125 modules / medium error correction for the 1,114-byte isolated fixture. The native canvas is 532px with a four-module quiet zone; its 460px browser rendering was decoded independently by ZXing. Actual distance, focus, glare and first-scan success on hardware are unmeasured.
- **TLS/SAN:** `make_identity` explicitly emits an IP-address SAN for the chosen bind address and loopback. The Swift protocol check actually completed positive TLS enrollment, upload/download and heartbeat as well as rejecting a wrong certificate. These are macOS client tests, not iPhone qualification. AVFoundation decodes the camera image; URLSession/Security handles iOS TLS. Android explicitly checks the leaf certificate digest and keeps hostname validation.
- **Clock:** the server enforces its stored invitation expiry; it never accepts a caller-supplied expiry as authority. Seconds are used in the compact payload. A badly skewed phone clock can reject an otherwise valid invitation early; no clock-skew tolerance is claimed.
- **Consume/Close race:** added 24 concurrent consume/revoke trials. SQLite serialization allows either completed pairing or revoked-unused invitation, never replay. Close does not revoke a session that already paired; the device's Revoke pairing control does. The desktop generation counter governs invitation creation responses, not a mobile enrollment response.
- **Trust/user intent:** desktop and phone both display the host and the same fingerprint prefix. The guide recommends the in-app scanner and documents custom-scheme non-exclusivity. Pairing alone does not send a prompt: host inference requires an authenticated run request; native remote mode also requires the selected node ID and the phone's LLM opt-in/model. This release does not add a separate approval registry, device attestation or protection against deliberate disclosure of a live invitation.
- **Credential lifetime:** the invite is deleted atomically and replaced by a separate random 256-bit bearer token delivered over pinned TLS; Android Keystore / iOS Keychain store the session. The invitation is not reused as the worker token. Cryptographic channel derivation is not required or claimed.
- **Admin/fallback:** status returns only `pending`; both new endpoints require the existing admin bearer token and loopback Host/Origin checks. Manual inputs and scanned inputs use the same new-ticket validator. Manual copying still leaves user-controlled clipboard exposure.
- **IP changes:** certificate SAN, bind address and generated invitation use the startup address. Existing state refuses an IP mismatch; the guide explains use of a new state directory and re-pairing after a network change. Network selection is not automatically repaired by QR scanning.

Physical camera scanning is the outstanding release qualification, and is disclosed in the experimental release notes and download metadata. None of this review establishes inference speed or large-model capacity.
